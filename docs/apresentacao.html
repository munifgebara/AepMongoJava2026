O que construímos?

Um CRUD didático de linguagens de programação

Cada linguagem possui id, nome, dataCriacao e autor.

Objetivos pedagógicos

  • Visualizar responsabilidades entre objetos.
  • Separar persistência de representação HTTP.
  • Praticar injeção de dependência e interfaces.
  • Comparar testes isolados e testes integrados.
  • Persistir documentos em um banco NoSQL real.

A viagem de um POST

1
O navegador envia JSON para POST /api/linguagens.
2
O Controller converte o JSON em LinguagemCreateRequest e aplica @Valid.
3
O Service coordena o caso de uso; o Mapper cria um Model sem ID.
4
repository.save envia o documento ao MongoDB, que gera o ID.
5
O Model salvo volta como LinguagemResponse, com status 201 e cabeçalho Location.

Infraestrutura

O Compose descreve o ambiente; a aplicação Java continua sendo executada separadamente.

compose.yaml · trecho resumido

services:
  mongo:
    image: mongo:${MONGO_VERSION:-7.0}
    environment:
      MONGO_INITDB_ROOT_USERNAME: ${MONGO_ROOT_USERNAME}
      MONGO_INITDB_ROOT_PASSWORD: ${MONGO_ROOT_PASSWORD}
    ports:
      - "127.0.0.1:${MONGO_PORT:-27018}:27017"
    volumes:
      - mongo-data:/data/db

  mongo-express:
    depends_on:
      mongo:
        condition: service_healthy

Boas decisões visíveis

  • Imagem com versão, sem latest.
  • Porta vinculada a 127.0.0.1.
  • Porta externa 27018 evita conflitos.
  • Volume usa o caminho oficial /data/db.
  • Mongo Express espera o banco ficar saudável.

DTOs são contratos de casos de uso

public record LinguagemCreateRequest(
    @NotBlank(message = "nome é obrigatório")
    String nome,

    @NotNull(message = "dataCriacao é obrigatória")
    LocalDate dataCriacao,

    @NotBlank(message = "autor é obrigatório")
    String autor) {}

Quatro contratos, quatro intenções

  • CreateRequest: entrada do POST, sem ID.
  • UpdateRequest: entrada do PUT, sem ID.
  • Response: detalhe completo.
  • SummaryResponse: lista com ID e nome.
Mesmo formato hoje não significa mesma responsabilidade amanhã.

    linguagem.setAutor(request.autor());

Usamos Hibernate?

Não.

  • Não há spring-data-jpa.
  • Não há @Entity ou @Table.
  • Não há SQL, JDBC ou EntityManager.
  • Hibernate é um ORM usado principalmente com bancos relacionais.

Usamos Spring Data MongoDB.

  • MongoRepository fornece operações.
  • MappingMongoConverter converte objeto ↔ BSON.
  • O MongoDB Java Driver envia comandos ao banco.
  • @Document mapeia classe para coleção.

Como save() grava?

1
Service entrega um objeto Linguagem ao Repository.
2
Spring Data lê @Document, @Id e as propriedades.
3
O converter produz BSON, preservando LocalDate conforme os codecs configurados.
4
Sem ID, ocorre inserção; com ID existente, o documento é substituído/atualizado.
5
O driver recebe a resposta e o Repository devolve o Model salvo.

Service: casos de uso e composição

@Service
public class LinguagemService {
    private final LinguagemRepository repository;
    private final LinguagemMapper mapper;

    public LinguagemService(
            LinguagemRepository repository,
            LinguagemMapper mapper) {
        this.repository = repository;
        this.mapper = mapper;
    }
}

Conceitos de OO visíveis

  • Encapsulamento dos casos de uso.
  • Composição de Repository e Mapper.
  • Injeção por construtor.
  • Dependência da interface do Repository.
  • Testabilidade pela substituição de colaboradores.

Atualizar sem perder o ID

public LinguagemResponse atualizar(
        String id, LinguagemUpdateRequest request) {

    Linguagem linguagem = buscarModelPorId(id); // ID vem da URL
    mapper.updateModel(request, linguagem);      // muda apenas dados editáveis
    return mapper.toResponse(
        repository.save(linguagem));             // persiste o mesmo documento
}

private Linguagem buscarModelPorId(String id) {
    return repository.findById(id)
        .orElseThrow(() -> new LinguagemNotFoundException(id));
}
Regra: o corpo do PUT não escolhe qual registro será atualizado.

const API_URL = "/api/linguagens";

async function requisitar(caminho = "", opcoes = {}) {
    const resposta = await fetch(
        `${API_URL}${caminho}`,
        {
            ...opcoes,
            headers: {"Content-Type": "application/json"}
        });

    if (!resposta.ok) {
        throw await resposta.json();
    }
    return resposta.status === 204
        ? null : resposta.json();
}

Limitações do ambiente local

MongoDB 8 × kernel Linux

A imagem mongo:8.0 recusou iniciar no host com kernel 7.0.0-28 e informou uma incompatibilidade conhecida com kernels 6.19+.

docker compose up -d
# padrão do projeto: MongoDB 7.0

A versão 7.0 virou o padrão compatível; MONGO_VERSION ainda permite substituição.

Mongo Express

A imagem está descontinuada pelos mantenedores. Foi mantida pela simplicidade em sala de aula.

Alternativas: MongoDB Compass ou DbGate.

Uso recomendado: somente estudo e desenvolvimento local.
